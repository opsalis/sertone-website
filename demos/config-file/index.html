Deployment Demo

One File. A Wrapper Configures Itself.

Drop a btw.yaml next to a Sertone wrapper and it sets itself up on boot — how it reaches the network, which identity it uses, and the services it hosts. No console clicking. Deploy one wrapper, or a thousand identical ones with Terraform, from the same file.

How It Works

The wrapper reads btw.yaml on boot and applies each section: network & storage, the identity it runs as, and the services it hosts. Then it comes up live on the mesh. Restart it and it reads the file again and comes back exactly as declared — so a fleet stays consistent and heals itself with no manual step.

Why a Config File?

The old way to set up a node was clicking through a web console — fine for one machine, painful for many. The config file makes a wrapper self-configuring: everything it needs is declared in one btw.yaml, so provisioning a wrapper is just placing a file and starting the process.

That is what makes fleets practical. Bake the file into a machine image or push it with Terraform or Ansible, and every box comes up the same way — each one an independent producer that serves its APIs and earns in USDC/USDT, with no per-machine clicking. And because the file is the source of truth, a wrapper that restarts re-reads it and comes back exactly as declared.

Boot a Wrapper From This File

btw.yaml (headless producer)

schema_version: 1

wrapper:
  data_dir: /var/lib/sertone
  mesh_listen: ":3991"

identity: {}            # create a persona on
                        # first boot, keep it

services:
  - type: appserver
    name: quotes
    fqdn_port: 127.0.0.1:8080
    pay_per_use: "0.001"  # USDC/call

  - type: website
    name: docs-site
    share_dir: /var/www/site

Self-Host in Minutes

1

Write the File

Put a btw.yaml next to the wrapper (or point BTW_CONFIG at it). Declare the network, identity, and the services this wrapper should host.

2

Start the Wrapper

Run the free Sertone container. On boot it reads the file and applies every section — no console step. A missing or invalid file stops the boot rather than starting half-configured.

$ docker run -d --name sertone \
  -v /path/to/btw.yaml:/app/btw.yaml \
  -v sertone-data:/app/data \
  {{INSTALL_IMAGE}}
3

Deploy the Fleet

Push the same file to as many machines as you want with Terraform, Ansible, or a machine image. Every wrapper comes up the same — independent producers, each earning in USDC/USDT.

4

It Self-Heals

Restart or replace a machine and the wrapper re-reads the file and comes back exactly as declared, with its identity preserved. No manual recovery.
